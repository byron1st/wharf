## Summary
local task 를 HTTP 로 관리하고 Jira 와 local task 를 함께 조회할 수 있도록 `/tasks` 목록·상세·생성·수정·삭제 API 를 추가했다. 계층은 plan 대로 server(디코딩·응답 매핑·상태 코드 표) → service(검증·local 전용 수정·not-found 변환) → db.Manager(읽기·수정·삭제 쿼리)이며, DEV-17 이월 항목(상태 코드 매핑, 자기 참조 검증, `WHF` 상수 유지, cross-origin parent 유지 규칙, 조회 인덱스)을 함께 반영했다.

## Red Flags
- **RF1** `internal/adapter/db/queries.sql.go:250` - 생성 코드에 `[]interface{}` 가 남는다: `make modelgen` 의 치환이 `db.go` 에만 걸리는 기존 Makefile 동작 때문이다. generated 라 lint 대상이 아니고 `make gen` 후 diff 도 없지만, 처음으로 `interface{}` 를 내는 쿼리(`sqlc.slice`)가 생겼다.
- **RF2** `scripts/queries.sql` `DeleteTaskNonLocalParent` - local parent 판별을 ID 접두어 `parent_id NOT LIKE 'local-%'` 로 한다. `task.NewID` 의 `{originated}-{key}` 형식에 의존하는 문자열 규칙이다.

## Open Questions
- **OQ1** `internal/service/service.go:116` - `UpdateTask` 는 `db.GetTask` 로 존재·origin 을 확인(트랜잭션 밖 읽기)한 뒤 `db.UpdateLocalTask` 로 쓴다. 그 사이에 task 가 삭제되면 `db.ErrLocalTaskToUpdateNotFound` 가 그대로 올라가 404 가 아니라 500 이 된다. 단일 사용자·단일 연결 전제에서 수락했지만, 404 로 보내려면 service sentinel 하나를 더 두면 된다.
- **OQ2** `internal/server/route.go:164` - `decodeTask` 는 JSON 객체 뒤의 추가 데이터(`{"title":"x"} xyz`)를 검사하지 않아 200/201 로 처리된다. plan 의 "잘못된 JSON 400" 범위를 객체 자체의 문법 오류로 해석했다.
- **OQ3** `internal/server/util.go:30` - 4xx 응답 본문은 `err.Error()` 그대로라 decode 실패는 `"server: failed to decode task request\njson: unknown field \"id\""` 처럼 개행이 포함된다. 클라이언트 표시 형식을 정할 때 다시 볼 만하다.
