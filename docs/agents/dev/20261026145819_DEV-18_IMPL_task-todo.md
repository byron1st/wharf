Task 하나에 귀속되는 flat Todo 를 추가했다. 0001 마이그레이션에 `todos`·`task_todos`(순서)·`todo_reminders` 를 두고, `db.Manager`·`service.Service` 에 todo 생성·목록(필터)·수정·삭제를 더하고, `GET/POST /todos`, `PUT/DELETE /todos/{id}` 라우트를 붙였다. task 삭제 시 그 task 의 todo 도 같은 트랜잭션에서 지운다. 판단 기준은 plan 의 Key decisions(정수 ID, `YYYY-MM-DD` 날짜, 쓰기 우선 트랜잭션, position 0..n-1 규칙)이다.

## Key Decisions
- 날짜 도메인 표현은 `string`("YYYY-MM-DD", 빈 값은 없음): 저장 형식과 같고 시간대 때문에 하루 밀릴 여지가 없다. `time.Time` 은 변환마다 위치를 신경써야 한다.
- `todo.Todo.Position` 은 `*int` 하나로 읽기(항상 설정)와 쓰기(nil = 끝/현재 위치 유지)를 겸한다. 별도 position 인자를 두는 시그니처보다 메서드가 단순하다.
- `UpdateTodo` 의 task 존재 확인은 첫 쓰기(`UPDATE todos`) 뒤의 `ExistsTask` 읽기로 한다. 같은 트랜잭션이라 실패 시 UPDATE 가 롤백되고, 쓰기 우선 규칙도 지킨다. 없는 todo 와 없는 task 가 겹치면 404 가 먼저다.
- reminder 정규화(UTC·정렬·중복 제거)는 service 에, 저장은 db 의 `ON CONFLICT DO NOTHING` 에 둔다. UTC 로 통일되어 텍스트 저장 순서가 시각 순서와 같다.
- 정수가 아닌 경로 id 는 server sentinel `ErrTodoIDNotInteger` 로 404.
